# Client requirements review — 6 November 2026

Implemented and checked locally:

- Players can replay the same game after a result, retaining their selected stake.
- Stake controls start at 0.5 points and increase/decrease in steps of 0.5.
- Player Activity and Recent Runs feeds are hidden. History still supports internal resume and personal-best calculations.
- Normal account creation and profile editing accept a blank email. Missing emails are stored as NULL and returned consistently to the UI.
- Wallet transfers and admin adjustments support fractional balances, with two-decimal validation in both UI and API.
- Completion retries return the original result without another payout. Failed ledger writes roll back the payout and session completion together.
- Starting/replaying has a synchronous guard against repeated clicks.
- The casino launcher no longer exposes an extra Exit button capable of cancelling an active animation. Individual games keep their own guarded exit controls.
- Resume finds unfinished sessions even when a newer completed round exists; exiting an idle game makes it resumable again.
- Switching or clearing authentication clears cached private data.
- Fractional supervisor outcomes are returned as numbers; PostgreSQL's global numeric parser is unchanged so unrelated numeric values retain their normal precision semantics.
- Migration 023 preserves the old BIGINT range and existing session stakes and ledger rows. Seed 008 also lowers minimums on fresh installations.

Validation:

- `npm test --prefix server`: 17 checks passed, covering validation, client/server payout calculations, isolated PostgreSQL execution, upgrade preservation, and React DOM player flows.
- `npm run build --prefix client`: TypeScript and production build passed.
- `git diff --check`: passed.
- Database integration uses an isolated PGlite PostgreSQL engine and never the configured DATABASE_URL. Native pgcrypto extension installation, live network concurrency, and browser layout were not exercised.

Remaining finding:

Casino outcomes are still generated by the browser and submitted as scores. Validating reachable scores and preventing duplicate payouts does not prevent a modified client from choosing a reachable winning score. Outcome generation and round state must move to the server to address this. The existing supervisor outcome endpoint also exposes presets to the player client, so those cannot serve as secret server-only results.

Deployment status:

These changes are local. Migration 023 and seed 008 have not been applied to the live database. Arcade game scores remain non-paying scores by the existing product rules; only Lucky Wheel, Slot Machine, Mines Field, and Crash Rocket credit winnings.
